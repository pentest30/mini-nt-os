# M7 bench: PeaZip 3.9.1 (Inno Setup), installed silently by APPBENCH.EXE
# (tests/native/appbench.c) from C:\APPS, then started and closed; the
# bench runs as the shell of the logged-on user (session).
# The markers say how far it goes; docs/compat/applications.md has the
# report.
features = test-smss, interactive
requires = userland, native
session = APPBENCH.EXE
boots = 2
app = peazip
cpus = default
timeout = 900
# What works today, a floor: the loader extracts its setup.tmp
# (SetEndOfFile: FileAllocationInformation), which finds the user an
# administrator (CheckTokenMembership: NtAccessCheck), creates its
# temporary directory and starts the installation: its Delphi edit box
# over comctl32 6's Edit, a Unicode class asked in ANSI, gets a call
# procedure (CALLPROCDATA, win32k::callproc; without it, the control wrote
# UTF-16 into the Delphi heap, and setup.tmp ended on STATUS_STACK_OVERFLOW).
# It installs, and peazip.exe opens its window and closes on WM_CLOSE: a
# name's long-name entries take a run of free slots of the directory
# (io::fat::FatVolume::add_entries; before, nographic-embedded had its long
# name in a hole that a moved file left and its 8.3 entry at the end, and
# PeaZip rolled back), see docs/compat/applications.md.
# Its route then extracts C:\APPS\ROUTE.ZIP (written by xtask, stored) by
# its command line, peazip.exe -ext2folder: PeaZip hands it to its 7-Zip and
# its launcher and ends first; the bench waits for C:\APPS\ROUTE\ROUTE.TXT
# and prints its two lines. Not yet: PeaZip's file manager stops on LCL's
# "Failed to get raw image description from bitmap" (24-bit bitmaps,
# refused by win32k), the "program window" above.
