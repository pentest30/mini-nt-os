# M5, console (docs/compat/m5-console.md, step 6): KEYS1.EXE
# (tests/native/keys1.c, MinGW, linked to ReactOS's kernel32 and user32)
# takes the place of winlogon.exe, which smss starts as its initial command
# once csrss runs. Like winlogon, it takes WinSta0\Default and loads the US
# keyboard layout; its window, shown, is activated: it becomes the
# foreground window and gets the keyboard (WM_ACTIVATE, WM_SETFOCUS). Once
# it is painted, QEMU's monitor types Shift+H, I and Enter: the PS/2
# controller interrupts, the i8042 driver decodes the bytes, the raw input
# thread gives each key to win32k, whose layout tables make it a virtual
# key, posted to the window's thread (WM_KEYDOWN, WM_KEYUP: Shift as
# VK_SHIFT, the scan code, KF_REPEAT and KF_UP); TranslateMessage posts the
# characters (WM_CHAR: H while Shift is down, then i, then Enter). A key's
# state is down (0x80) and toggled at each press (1): Shift, pressed once,
# stays toggled. On Enter, the thread's key state (GetKeyState,
# GetKeyboardState: as of the messages processed), the keyboard's
# (GetAsyncKeyState) and ToUnicodeEx. DefWindowProc gives the window the
# keyboard on WM_ACTIVATE (SetFocus). Then the program takes the keyboard
# from its window (SetFocus(NULL)), and A, typed, is a system key for the
# active window (WM_SYSKEYDOWN, WM_SYSKEYUP), after which SetFocus gives it
# back.
