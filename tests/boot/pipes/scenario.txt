# M5, named pipes (NPFS, docs/compat/m5-csrss.md, step 24): PIPE1.EXE
# (tests/native/pipe1.c, MinGW, linked to ReactOS's kernel32) takes the
# place of winlogon.exe, which smss starts as its initial command once csrss
# runs; smss has made \??\PIPE lead to \Device\NamedPipe (DOS Devices).
# - A message pipe, \\.\pipe\mino\test, whose server is overlapped like
#   rpcrt4's: NtCreateNamedPipeFile, then FSCTL_PIPE_LISTEN pending on an
#   event; a client thread waits for an instance (FSCTL_PIPE_WAIT on the
#   root, \DosDevices\pipe\), opens the pipe (NtCreateFile: it connects, the
#   listen ends and its event is set), reads in message mode
#   (NtSetInformationFile, FilePipeInformation), writes two messages and
#   waits for a reply (a synchronous read that waits in the kernel). The
#   server peeks (FSCTL_PIPE_PEEK), reads 3 bytes of the first message
#   (STATUS_BUFFER_OVERFLOW: ERROR_MORE_DATA), then the rest, then the
#   second; its next read waits (STATUS_PENDING), it replies, and the
#   client's close ends that read (STATUS_PIPE_BROKEN, written by the
#   client's thread into the server's OVERLAPPED). Then the pipe's local
#   information, a disconnect, a listen cancelled by NtCancelIoFile, the
#   limit of two instances (ERROR_PIPE_BUSY), a busy pipe (ERROR_PIPE_BUSY)
#   and a wait that runs out of time (ERROR_SEM_TIMEOUT), and the pipe gone
#   with its last instance (ERROR_FILE_NOT_FOUND).
# - An anonymous pipe (CreatePipe: byte mode, synchronous, a quota of 16
#   bytes): a read across two writes, a write of 40 bytes that waits until
#   reads free the quota, a read that waits for a write, and a read once the
#   writer is closed (ERROR_BROKEN_PIPE). GetFileType gives FILE_TYPE_PIPE
#   (3: FileFsDeviceInformation, FILE_DEVICE_NAMED_PIPE).
