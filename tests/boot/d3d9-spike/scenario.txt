# M8 spike: a Direct3D 9 triangle (tests/native/d3d1.c) through the pinned
# ReactOS stack: d3d9, Wine's wined3d (d3dwine.dll), opengl32.dll
# (docs/compat/m8-direct3d.md). What works today, a floor: win32k announces
# the display driver's OpenGL ICD (NtGdiExtEscape: QUERYESCSUPPORT, then
# OPENGL_GETINFO gives "Mesa", ADR-025), opengl32 finds OpenGLDrivers\Mesa
# (mino.inf) with the same versions and tries mesaicd.dll, not yet on the
# disk: it keeps its software renderer. wined3d makes its hidden window (a
# class found from a null instance) and a GL context on it (WindowFromDC,
# NtGdiGetDCDword(GdiGetIsMemDc)), reads the GL renderer, then finds no pixel
# format it keeps: all 36 formats of the pinned opengl32 are
# PFD_GENERIC_FORMAT, which wined3d refuses without WGL_ARB_pixel_format, and
# Direct3DCreate9 returns NULL. With the ICD on the disk (step 3 of the spike)
# the floor goes up to the triangle. What win32k says of pixel formats, as
# ReactOS with a framebuffer driver: none described, none set or swapped.
