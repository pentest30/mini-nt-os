# M6, the logon (ADR-023, docs/compat/m5-csrss.md step 27). The hives of
# the boot disk carry the Mino layer (tools/mkhive/mino.inf): the first
# boot is in setup mode, the second goes to the logon. Two boots on the
# system disk, so that what the first writes (the hives, the profiles) is
# there for the second.
#
# First boot: samsrv makes the accounts (setup mode), winlogon starts
# MINOINIT.EXE (SYSTEM\Setup\CmdLine), which waits for Administrator in
# the SAM, makes the profiles (userenv's InitializeProfiles: C:\Documents
# and Settings, a long-named directory), copies HKU\.DEFAULT, written back,
# as NTUSER.DAT of Default User, sets SetupType = 0, writes the hives back
# and reboots. Every step logs "[minoinit] ..."; a failed step stops it
# ("[minoinit] stopped: ..."). It also logs its environment: smss passes on
# SystemDrive, which the kernel gives it as ReactOS's does.
#
# Second boot: winlogon goes to the logon, msgina logs Administrator on
# (AutoAdminLogon) through LsaLogonUser; msv1_0 finds the account and its
# blank password in the SAM, and lsasrv stops at NtCreateToken: where the
# logon stops today.
#
# `interactive`: the probe waits for smss for good (the reboot ends the
# first boot); without it, it would end smss 10 s after its start.
#
# Few markers: the serial log can cut a line with another thread's
# (docs/passation.md, the debts of step 27).
features = test-smss, interactive
requires = userland, native
disk = system
boots = 2
cpus = default
timeout = 300

expect = [boot] .DEFAULT hive mounted at \REGISTRY\USER\.DEFAULT
expect = [minoinit] environment: SystemDrive=C:
expect = [minoinit] done; rebooting
expect = sys: NtCreateToken (0x0039) is not implemented

forbid = [minoinit] stopped:
forbid = *** STOP:
