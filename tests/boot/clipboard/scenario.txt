# The clipboard (win32k::clipboard, tests/native/clip1.c, MinGW, linked to
# ReactOS's kernel32 and user32): CLIP1.EXE takes the place of winlogon.exe
# and takes WinSta0\Default; it writes to the clipboard, then starts itself
# again as the reader ("C:\CLIP1.EXE reader"), another process, which reads
# what the writer put, formats synthesized by user32 included, and takes
# the clipboard. Update with docs/compat/m6-fenetres.md, step 45.
# 1. SetClipboardViewer: WM_DRAWCLIPBOARD to the new viewer.
# 2. Errors: closed (1418), a bad window (1400), opened by another window
#    (5), another thread's (1418).
# 3. Written: 3 formats, then 6 at the close (CF_LOCALE, CF_TEXT,
#    CF_OEMTEXT added, the sequence +7: EmptyClipboard, 3 SetClipboardData,
#    3 synthesized), their order, a registered format's name, priorities.
# 4. The reader: the text in CF_UNICODETEXT, and in CF_TEXT and CF_OEMTEXT
#    (é: E9 in code page 1252, 82 in 437), CF_LOCALE, the private format by
#    its name, the delayed format rendered by the writer's window
#    (WM_RENDERFORMAT across processes); EmptyClipboard (WM_DESTROYCLIPBOARD
#    to the writer's window, which still sees its 6 formats), then it ends
#    with the clipboard open: its end closes it.
# 5. The writer: closed, no owner, the reader's text after its end.
# 6. The viewer chain (WM_CHANGECBCHAIN to its head).
# 7. A destroyed owner: WM_RENDERALLFORMATS, its unrendered delayed format
#    gone.
