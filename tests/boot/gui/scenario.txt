# M6, windows: GUI1.EXE (tests/native/gui1.c, MinGW, linked to ReactOS's
# kernel32 and user32) takes the place of winlogon.exe, which smss starts as
# its initial command once csrss runs. Like winlogon, it registers as the
# logon process, creates WinSta0 and a desktop and goes on it; user32 reads
# the system metrics and colours in the shared section. Then it
# registers a window class (user32 registers its system controls first),
# finds it and user32's Button again (GetClassInfoExW), cannot find a class
# never registered nor register its own twice. It creates a window of its
# class: its procedure receives WM_NCCREATE and WM_CREATE (the CREATESTRUCT
# as given; meanwhile the TEB's CLIENTINFO names the window and its WND),
# WM_NCCALCSIZE, WM_SIZE and WM_MOVE, through KeUserModeCallback;
# user32 reads by itself its name, style and rectangle in its WND; its name
# changes (SetWindowTextW: WM_SETTEXT, NtUserDefSetText). A child window
# tells its parent (WM_PARENTNOTIFY), which user32 finds through the WNDs'
# links. A child without a parent, a window of no class and one whose
# procedure refuses WM_NCCREATE are not created. An overlapped window gets
# WM_GETMINMAXINFO first (the limits from the system metrics), the place
# and size of ReactOS without a monitor, and its client area from the
# kernel's DefWindowProc (NtUserMessageCall, WM_NCCALCSIZE: without the
# frame and the caption, and WNDS_HASCAPTION in its WND; with valid
# rectangles, WVR_VALIDRECTS). Sizing windows stay within WM_GETMINMAXINFO's
# limits, those the system gives or a larger minimum from their procedure;
# they are created with ones on the stack, which user32 leaves in the bAnsi
# bit of the class name's LARGE_STRING. The monitor (MonitorFromWindow,
# MonitorFromPoint, GetMonitorInfoW) gives overlapped windows their default
# place, in cascade, and size (3/4 of the screen). SetWindowPos and
# MoveWindow move and size windows (WM_WINDOWPOSCHANGING, WM_GETMINMAXINFO's
# limits, WM_NCCALCSIZE, WM_WINDOWPOSCHANGED, WM_MOVE, WM_SIZE), move a
# child with its parent (WM_CHILDACTIVATE to an activated child), order
# windows (top, bottom, after a sibling, topmost) and show or hide them.
# It ends with status 0x600D.
# Update with each step (docs/compat/m6-fenetres.md).
