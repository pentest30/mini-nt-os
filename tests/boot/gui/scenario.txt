# M6, windows: GUI1.EXE (tests/native/gui1.c, MinGW, linked to ReactOS's
# kernel32, user32 and gdi32) takes the place of winlogon.exe, which smss starts as
# its initial command once csrss runs. Like winlogon, it registers as the
# logon process, creates WinSta0 and a desktop and goes on it; user32 reads
# the system metrics and colours in the shared section, gdi32 the brush of
# a system colour in the GDI handle table. Then it
# registers a window class (user32 registers its system controls first),
# finds it and user32's Button again (GetClassInfoExW), cannot find a class
# never registered nor register its own twice. It creates a window of its
# class: its procedure receives WM_NCCREATE and WM_CREATE (the CREATESTRUCT
# as given; meanwhile the TEB's CLIENTINFO names the window and its WND),
# WM_NCCALCSIZE, WM_SIZE and WM_MOVE, through KeUserModeCallback;
# user32 reads by itself its name, style and rectangle in its WND; its name
# changes (SetWindowTextW: WM_SETTEXT, NtUserDefSetText). A child window
# tells its parent (WM_PARENTNOTIFY), which user32 finds through the WNDs'
# links. A child without a parent, a window of no class and one whose
# procedure refuses WM_NCCREATE are not created. An overlapped window gets
# WM_GETMINMAXINFO first (the limits from the system metrics), the place
# and size of ReactOS without a monitor, and its client area from the
# kernel's DefWindowProc (NtUserMessageCall, WM_NCCALCSIZE: without the
# frame and the caption, and WNDS_HASCAPTION in its WND; with valid
# rectangles, WVR_VALIDRECTS). Sizing windows stay within WM_GETMINMAXINFO's
# limits, those the system gives or a larger minimum from their procedure;
# they are created with ones on the stack, which user32 leaves in the bAnsi
# bit of the class name's LARGE_STRING. The monitor (MonitorFromWindow,
# MonitorFromPoint, GetMonitorInfoW) gives overlapped windows their default
# place, in cascade, and size (3/4 of the screen). SetWindowPos and
# MoveWindow move and size windows (WM_WINDOWPOSCHANGING, WM_GETMINMAXINFO's
# limits, WM_NCCALCSIZE, WM_WINDOWPOSCHANGED, WM_MOVE, WM_SIZE), move a
# child with its parent (WM_CHILDACTIVATE to an activated child), order
# windows (top, bottom, after a sibling, topmost) and show or hide them.
# ShowWindow shows (WM_SHOWWINDOW, SetWindowPos, then the WM_SIZE and WM_MOVE
# an overlapped window waited for; the thread's first activation takes the
# foreground, so WM_ACTIVATEAPP, to each of its top-level windows, comes
# before WM_NCACTIVATE) and hides windows; a child of a hidden
# window only gets WS_VISIBLE; windows created visible are shown, with the
# command in y for an overlapped window placed by default. A window shown
# or changed paints its frame (WM_NCPAINT) then erases its client area
# (WM_ERASEBKGND, with a cache DC of the kernel cut to what shows of it:
# GetClipBox gives a simple or a complex region) at once; the DC given back,
# GetClipBox and PatBlt refuse it.
# Regions of GDI live in the GDI handle table with their attributes in the
# process (RGN_ATTR), which gdi32 reads (GetRgnBox) and changes itself for
# a rectangle (CombineRgn(RGN_AND), SetRectRgn), the kernel taking them back
# (CombineRgn(RGN_OR) after SetRectRgn); DeleteObject, queued in the TEB,
# gives the entry back, which a new region takes again, once more reused.
# GetDC, GetWindowDC and GetDC(NULL) give DCs of the client area, of the
# whole window and of the whole screen, which ReleaseDC (or DeleteDC) gives
# back once;
# GetDCEx cuts one by a region on the screen (DCX_INTERSECTRGN), deleted
# when it is given back, or without it (DCX_EXCLUDERGN | DCX_KEEPCLIPRGN),
# kept. SelectClipRgn, queued in the TEB (its result from the DC's
# VisRectRegion), and ExtSelectClipRgn(RGN_OR) cut where a DC paints.
# InvalidateRgn, ValidateRgn and GetUpdateRgn work on the update region,
# RedrawWindow(RDW_ERASENOW) erases a region of it at once; with only the
# caption to paint, GetUpdateRgn empties the region. A second thread goes,
# at its first call to user32, on the process's startup desktop
# (IsWindowVisible) and posts to a window of the first thread, whose queue
# gets the message for the window (PostMessageW, PeekMessageW). A top-level
# window created with a menu has its menu bar from its creation (its client
# area SM_CYMENU less tall); with a menu that does not exist, no window
# (ERROR_INVALID_MENU_HANDLE). Without one, it takes its class's menu (one of
# shell32's, by its name or its identifier): user32 loads it for an overlapped
# window, win32k asks user32 for it for a plain WS_OVERLAPPED (the LoadMenu
# callback).
# It ends with status 0x600D, 5 s after `[gui] done`: its windows go with
# its process, and the screen is captured meanwhile.
# Update with each step (docs/compat/m6-fenetres.md).
