Le projet

Les bases d'un système, sans raccourcis.

Mino avance par étapes : du démarrage UEFI aux composants du noyau, avec une attention particulière portée à la documentation, aux tests et à la conformité des composants réutilisés. Même objectif que ReactOS, répartition du travail différente.

Rs

Noyau en Rust

Tout le code privilégié est écrit en Rust no_std : le noyau ntoskrnl, la partie noyau du sous-système Win32 (win32k) et les pilotes, dans un workspace organisé par sous-systèmes.

UEFI

Démarrage moderne

Un chargeur UEFI écrit en Rust démarre le noyau. QEMU avec OVMF (q35) est la plateforme de référence pour le développement, VirtualBox (EFI) la plateforme de test secondaire.

XP

Compatibilité visée

Le projet explore la compatibilité avec des applications et jeux 32 bits de l'ère XP (2001–2008), sans les modifier. Un objectif en cours de développement, pas une promesse de compatibilité actuelle.

Code privilégié : Rust Espace utilisateur : ReactOS / Wine, binaires épinglés Version visée : NT 5.1.2600 (ADR-003) Licence : MIT pour l'instant (ADR-007 ouvert)

ÉPOQUE XP

Applications PE32 i386

Les exécutables 32 bits de l'époque XP (2001–2008) tournent sans modification : explorer, notepad, jeux Direct3D 8/9, installeurs. Le système se présente aux applications comme XP (5.1.2600).

  • ABI utilisateur : PEB, TEB, KUSER_SHARED_DATA, SEH chaîné via FS:[0]
  • Vérifiée par les suites rostests de ReactOS
  • Programmes 16 bits (DOS, Win16) hors périmètre

Séquence de démarrage

Du firmware au bureau, la chaîne décrite dans le document 02 §3 — le chargeur ne charge que le noyau et le hive SYSTEM :

1 Firmware UEFI→ 2 mino-loader.efi→ 3 ntoskrnl phase 0→ 4 phase 1 : pilotes, Cm, Io, ntdll→ 5 smss.exe→ 6 csrss.exe + win32k→ 7 winlogon.exe→ 8 explorer.exe
Démarrage rapide

Compiler, tester, lancer.

La chaîne de construction passe par cargo xtask. Les tests de boot tournent en QEMU sans affichage et sont validés par des marqueurs sur la sortie série.

SHELL — OUTILLAGE
# Installe la toolchain nightly épinglée (rust-toolchain.toml)
rustup toolchain install
SHELL — TESTS
# Tests hôte, puis tests de boot QEMU headless,
# validés par des marqueurs sur la sortie série
cargo xtask test
SHELL — EXÉCUTION
# Démarre l'OS dans QEMU, sortie série redirigée vers stdio
cargo xtask run

# Toutes les options disponibles
cargo xtask help
SHELL — DÉPENDANCES (DEBIAN / UBUNTU)
# QEMU et OVMF doivent être installés
sudo apt install qemu-system-x86 ovmf

Configuration minimale

  • Rust nightly épinglé — la version exacte est fixée par rust-toolchain.toml (ADR-016, dépendances no_std auditées)
  • QEMU (OVMF, q35) — plateforme de référence : tests automatisés et CI
  • VirtualBox (EFI) — plateforme de test secondaire
  • Matériel réel x86-64 UEFI — prévu à partir du jalon M9
  • Hors périmètre — BIOS sans UEFI, CPU 32 bits (ADR-001)
Version en cours

Où en est Mino ?

Le README du dépôt indique le jalon M1 — noyau Ke (M0 terminé). Les jalons sont séquentiels et sans dates : l'ordre est imposé par les dépendances techniques. Un jalon est terminé quand tous ses critères de sortie passent en CI.

Le développement continue.

Mino est un projet expérimental : ses fonctions et sa compatibilité évoluent avec le travail en cours. L'état de référence reste le README et la feuille de route du dépôt.

M1Noyau KeEN COURS

De vrais threads : dispatcher (événements, sémaphores, mutants, timers), ordonnanceur à 32 priorités, APC et DPC sans allocation, IRQL via le TPR, sauvegarde FPU/SSE, écran d'erreur fatale KeBugCheckEx symbolisé.

○
M2Mémoire, objets, processusÀ VENIR

De vrais processus : base PFN et pools, une PML4 par processus, VAD et fautes de page à la demande, Ob complet, EPROCESS/ETHREAD, PEB32 et TEB32.

○
M3Frontière NTÀ VENIR

Faire tourner le ntdll de ReactOS : tables d'appels générées, portes int 2Ah–2Eh, SWAPGS, livraison des exceptions et des APC utilisateur, spike S1.

○
M4E/S, registre, systèmes de fichiersÀ VENIR

Lancer smss.exe : IRP et piles de périphériques, pilotes ATA et virtio-blk, FAT32 en lecture/écriture, registre au format regf généré par mkhive.

○
M5Mode consoleÀ VENIR

Un cmd.exe interactif : Lpc complet, Se (jetons, mode permissif), csrss et kernel32, spike S2.

○
M6win32kÀ VENIR

Des fenêtres : spike S3 d'abord (point qui confirme l'ADR-002), USER et GDI, callbacks noyau → utilisateur, pilotes gopfb et bochs-dispi, souris i8042.

○
M7Bureau et applicationsÀ VENIR

Un système utilisable au quotidien en machine virtuelle : explorateur, panneau de configuration, Paint, calculatrice, installeurs MSI / InstallShield / NSIS, thème libre de style XP (aucune ressource Microsoft).

○
M8Multimédia et jeuxÀ VENIR

Faire tourner le jeu de référence : pile Direct3D (wined3d puis Mesa en rendu logiciel), son, DirectInput. Ghost Recon (GOG) atteint le menu principal puis une mission jouable.

○
M9Matériel réel et réseauÀ VENIR

AHCI, NVMe, USB xHCI, ACPI, virtio-net et e1000, pile TCP/IP en Rust, AFD, NTFS en lecture seule. Démarrage sur au moins deux machines physiques UEFI de référence.

○
M10MaturitéÀ VENIR

SMP, sécurité appliquée, fichier d'échange, NTFS en écriture, installeur graphique, remplacement progressif des DLL ReactOS par du Rust quand la mesure le justifie.
